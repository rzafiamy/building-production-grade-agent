  FORMAT, LAYOUT & DESIGN SPECIFICATION — "The Autonomous Agent"
═══════════════════════════════════════════════════════════════════════════════

OVERVIEW
────────
The book is authored in Markdown (CommonMark + GFM extensions). It is
designed to render correctly in:
  - GitHub / GitLab markdown viewers
  - Static site generators (VitePress, Docusaurus, Nextra)
  - PDF export via Pandoc or similar
  - Print-on-demand after PDF export

Each page is one `.md` file. Files are named with a zero-padded prefix for
natural sort order: `00-cover.md`, `01-title-page.md`, `08-ch01-...md`, etc.

FILE NAMING CONVENTION
──────────────────────
Format: `{NN}-{slug}.md`

  00–07   Front matter (cover, title, copyright, dedication, etc.)
  08–12   Part I chapters
  13–18   Part II chapters
  19–28   Part III chapters
  29–33   Part IV chapters
  34–41   Part V chapters
  42–48   Part VI chapters
  49–53   Part VII chapters
  54–59   Back matter (appendices, glossary, bibliography)

TYPOGRAPHY (Markdown Representation)
──────────────────────────────────────
H1 (#)     — Book title and part titles only. One per file maximum.
H2 (##)    — Chapter titles (one per chapter file).
H3 (###)   — Major section headings within a chapter.
H4 (####)  — Sub-sections. Use sparingly.

Body text: plain prose paragraphs separated by blank lines.
Emphasis (*italic*): for introducing terms and light stress.
Strong (**bold**): for critical warnings, API names in prose, key terms.
Code (`backtick`): ALL class names, method names, file paths, config keys,
                   and any literal string that would appear in code.

Never use underline, strikethrough, or superscript in body text.

CODE BLOCKS
──────────────
Use triple-backtick fenced blocks with language tag always:

  ```typescript
  // code here
  ```

Supported language tags in this book:
  typescript, javascript, bash, json, yaml, text, pseudocode

Inline code: use single backticks. Keep inline code short (< 60 chars).

For terminal commands, use `bash` blocks:
  ```bash
  pnpm add lemura
  ```

For file paths shown as output or config, use `text`:
  ```text
  src/agent/SessionManager.ts
  ```

CALLOUT BOXES (GitHub Flavored Markdown alerts)
───────────────────────────────────────────────
> [!NOTE]
> Supplementary information that enriches understanding.

> [!TIP]
> Non-obvious tricks or shortcuts that save time.

> [!WARNING]
> Common mistakes or patterns that cause bugs in production.

> [!DANGER]  (rendered as CAUTION in some systems)
> Security risks, data loss scenarios, irreversible operations.

Keep callout content to 1–4 sentences. Never nest callouts.

TABLES
──────
Use GFM tables for:
  - Configuration reference (key | type | default | description)
  - Comparison tables (feature | approach A | approach B)
  - API quick-reference

Align number columns right, text columns left.
Always include a header row with `---` separator.

DIAGRAMS
────────
Use ASCII art for architecture and flow diagrams. Wrap in a `text` block:

  ```text
  ┌──────────────┐     tool call    ┌──────────────┐
  │  LLM Engine  │ ──────────────▶  │  Tool Runner │
  │              │ ◀──────────────  │              │
  └──────────────┘     result       └──────────────┘
  ```

Preferred ASCII box characters: ┌ ┐ └ ┘ │ ─ ├ ┤ ┬ ┴ ┼ ▶ ◀ ↑ ↓
(These render correctly in most monospace fonts.)

FRONT MATTER FORMAT (YAML, each .md file)
──────────────────────────────────────────
Each chapter/page file should begin with YAML front matter:

  ---
  title: "Chapter Title"
  part: "Part N — Part Name"
  chapter: N
  page: NN
  status: draft | review | final
  ---

This front matter is used by the static site generator and PDF toolchain.

PAGE LAYOUT (for print/PDF export)
────────────────────────────────────
Page size:          6" × 9" (standard trade paperback)
Margins:            0.75" all sides
Body font:          Source Serif 4, 11pt
Code font:          JetBrains Mono, 9pt
Heading font:       Inter, weights 600 (H3/H4) and 700 (H1/H2)
Line height:        1.55 for body, 1.3 for code
Chapter title size: 24pt (H2)
Section size:       16pt (H3)
Sub-section size:   13pt (H4)

Color palette (for rendered/PDF version):
  Background:     #FFFFFF (white print) / #0F0F11 (dark web)
  Body text:      #1A1A1A (print) / #E8E8E8 (dark web)
  Code bg:        #F5F5F5 (print) / #1A1A2E (dark web)
  Accent/headers: #1A56DB (blue)
  Warning boxes:  #FFF3CD background, #856404 border
  Danger boxes:   #F8D7DA background, #721C24 border
  Note boxes:     #D1ECF1 background, #0C5460 border
  Tip boxes:      #D4EDDA background, #155724 border

CHAPTER PAGE STRUCTURE (ORDER OF ELEMENTS)
────────────────────────────────────────────
1. YAML front matter
2. Part label (small caps, dimmed): "PART III — LEMURA FRAMEWORK"
3. Chapter number (large, accent color): "Chapter 12"
4. Chapter title (H2)
5. Chapter epigraph (optional): a short relevant quote in italic
6. Chapter Goal box (> [!NOTE] "By the end of this chapter, you will...")
7. Body sections (H3 → H4 → prose → code)
8. Key Takeaways section (## Key Takeaways, bulleted list)
9. Optional: Further Reading (1–3 items, no URLs)

PART INTRO PAGE STRUCTURE
──────────────────────────
1. YAML front matter
2. Part number (H1, large)
3. Part title (H2)
4. Part overview (2–4 paragraphs): what this part covers and why it matters
5. Chapters in this part (simple list with one-line descriptions)

FRONT MATTER PAGES
──────────────────
  cover.md        — Book cover (title, subtitle, author, version)
  title-page.md   — Full title page with publisher info
  copyright.md    — Copyright, license, credits
  dedication.md   — Author's dedication
  foreword.md     — Foreword (tone: contextual, by a trusted voice)
  preface.md      — Author's preface: motivation, who this is for, how to read
  toc.md          — Table of contents (links to all pages)

BACK MATTER PAGES
──────────────────
  appendix-a      — Lemura Full API Reference
  appendix-b      — Configuration Key Reference (SessionConfig)
  appendix-c      — Glossary of Terms
  appendix-d      — Further Reading & Resources
  bibliography    — Works cited / referenced
  about-author    — Author bio
